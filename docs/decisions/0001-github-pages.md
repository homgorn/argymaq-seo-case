# ADR 0001 — GitHub Pages вместо Cloudflare

**Дата:** 15 ноября 2026
**Статус:** принято

## Контекст

Владелец подключает GitHub Pages сам и держит репозиторий на GitHub. Скилл
`blueprint-site-astro-cloudflare` по умолчанию предлагает Cloudflare Workers
или Pages — это быстрее и даёт CDN, но требует отдельного аккаунта и настройки
DNS.

## Решение

Деплой на **GitHub Pages**, источник — ветка `main`, каталог `/docs`.

Причины:

1. Владелец уже ведёт репозиторий на GitHub и сам подключает Pages.
2. Не нужен второй аккаунт и transfer домена.
3. Для статического сайта из 17 страниц разница в скорости CDN не критична.

## Следствия

| Что | Как |
|---|---|
| Каталог сборки | `site/dist` — рабочий |
| Каталог публикации | `docs/` — туда копируется содержимое `dist` |
| `.nojekyll` | обязателен, иначе `_astro/` не отдаётся |
| Base в Astro | `/argymaq-seo-case` |
| CI | отключён: аккаунт GitHub упёрся в биллинг, Actions не запускаются |
| Деплой | вручную: `npm run build`, копия в `docs/`, push |

## Что теряем

- Нет CDN и автоматического сжатия на границе.
- Нет preview-деплоев на pull request.
- Деплой руками, а не по git push.

## Альтернативы, отклонённые

| Вариант | Почему нет |
|---|---|
| Cloudflare Pages | нужен аккаунт, владелец не просил |
| Netlify / Vercel | то же + биллинг |
| Свой VPS | дороже в поддержке |
| Оставить Actions | аккаунт заблокирован по биллингу |

## Как вернуться к Actions

Когда биллинг GitHub будет пополнен:

1. Вернуть `.github/workflows/pages.yml` в работу.
2. Убрать `docs/` из публикации, оставив `site/dist`.
3. Настроить Pages на `build_type=workflow`.

Каталог `docs/` тогда можно будет убрать — но **только с подтверждения владельца**,
так как он содержит и вики, и документацию.
